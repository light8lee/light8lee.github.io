# 文章详情页相关推荐设计

## 目标

在所有文章详情页提供最多 5 篇相关推荐，让读者能从当前主题继续浏览历史内容。候选内容包括 `_posts`、书架独立页和 Daydream；不改变首页、归档页或内容原文。

## 范围与内容资格

候选内容必须有可访问链接、标题，并且使用站点的可阅读内容布局。构建资产、导航页面、草稿、`published: false` 页面和当前页面均不参与。没有符合资格的候选时，不渲染空的相关推荐栏目。

## 推荐架构

使用 Jekyll 在每个文章页内生成一份候选内容的轻量数据集（标题、链接、标签）。浏览器端脚本在页面加载时计算相似度并填充栏目。

这样能在 GitHub Pages 可用的构建范围内自动覆盖新增的文章、书架页和 Daydream，不引入自定义 Jekyll 插件、外部服务或手工维护的索引文件。

## 排序规则

每个候选条目依以下规则累计分数：

1. 每个共同 tag 提供主要权重。
2. 标题的规范化关键词相同或包含时提供次级权重；中英文标题均按可用词片段处理。
3. 有共同 tag 的结果排在只有标题关联的结果之前；同分时按发布日期由新到旧稳定排序。
4. 过滤无共同 tag 且无标题关联的内容，取前 5 个。

当前文章、重复 URL、隐藏页和不具备链接的内容必须在评分前剔除。

## 页面与响应式行为

桌面端扩展现有 `.post-layout` 为“左目录—正文—右相关推荐”三列。相关推荐随滚动固定在可视范围内，展示栏目标题、简短说明、最多 5 个标题链接和共同 tag。

移动端保留现有目录折叠行为，将相关推荐放在正文及已有系列导航之后，取消 sticky，避免小屏横向滚动。链接应有键盘焦点和悬停状态。

## 失败与降级

脚本异常、候选数据为空或没有正分候选时，栏目保持隐藏，不影响正文阅读。脚本不请求第三方服务，也不存储读者数据。

## 验收与测试

- 自动化测试覆盖：跨三种内容来源采集候选、排除当前页/隐藏页/重复 URL、tag 优先、标题次级匹配、仅保留 5 项及空结果隐藏。
- Jekyll 构建成功，且生成详情页包含候选数据与无障碍导航语义。
- 浏览器验证桌面端三列/sticky 栏目、实际链接数量与候选来源；390px 验证相关推荐位置及无横向溢出。
- `git diff --check` 无格式问题。
