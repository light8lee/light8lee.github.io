# 低概率 Token，为什么不该无限主导 SFT 更新？

标准 SFT 会逐 token 地提高专家答案的概率。若某个参考 token 对模型非常陌生，负对数似然会给它很强的拟合压力；可是在推理与代码任务中，低概率有时只意味着罕见措辞、变量命名或等价实现路线，而不一定意味着模型缺少决定任务成败的知识。

ICML 2026 Spotlight 论文 [Don't Force the Fit: Bounded Log-Likelihood Loss for Enhanced Reasoning in Large Language Models](https://openreview.net/forum?id=mTMA9yvsnx) 提出 BLL-Loss。它保留训练样本，也不按整条回答简单降权；它在低概率 token 区域限制单个 token 对更新的梯度贡献，同时使常规概率区域保持接近最大似然训练的行为。

### 低概率，不等于低价值；更不等于必须无限用力拟合

“模型不会，所以更该教”对于新事实或关键逻辑通常正确；但它默认所有低概率 token 都代表同一种能力缺口。想象参考代码使用 `accumulator_state_v2`，学生更倾向等价的 `state`：控制流、返回值和测试结果不变，罕见命名本身却可能带来更强的逐字拟合压力。

论文针对的不是错误示范或 label noise，而是更细的 **optimization misalignment**：专家轨迹可以完全正确，但任务允许不止一种正确实现；训练目标仍会把其中一个实现的每个 token 当作唯一参考。问题是优化力度是否因此过度落在偶发的表面形式上。
</div>
</section>

### BLL-Loss 改的是局部优化几何，不是训练范式

论文题目中的 “Don't Force the Fit” 指向一个窄问题：正确示范是否意味着每一个 token 都应以无界力度被复刻？BLL-Loss 保留监督学习、保留原训练样本，也不需要额外可学习参数；它只在低概率区域改变单个 token 对更新的最大牵引力。

这使它与“先筛掉困难数据”或“重写输出答案”不同。它是一种 SFT 内部的 loss 设计，目标是在保持专家示范信息的同时，为多种等价的推理、代码和表达路径留下更大的空间。
</div>
</section>

### 两段都正确，为什么一段会获得更重的逐字监督？

在代码中，变量命名、代码重排和若干等价控制表达可以不同而测试同样通过；在数学证明中，同一结论也可能由不同引理顺序或语言表述得到。任务验证器关心的是语义、执行或最终答案，参考字符串匹配则关心其中一种实现。

这张卡不是论文实验复现，而是解释“等价实现”这一动机。它强调低概率的两种来源必须区分：可能是模型没学会关键知识，也可能只是参考答案选了模型不常用的风格。BLL 的立场不是预先判定哪一种，而是避免后一种在极端概率区无限放大。
</div>
</section>

### 标准 SFT 的目标只知道“参考答案选了它”

标准 SFT 通常最小化参考序列的负对数似然：

$$
\mathcal L_{\rm SFT}=-\sum_t\log p_\theta(y_t\mid x,y_{<t}).
$$

当参考 token 的 $p_\theta$ 很低，$-\log p_\theta$ 很大，训练便更强地推动模型提高该 token 的概率。这是最大似然的自然结果，并不构成缺陷；它的盲点在于损失不会自行识别“罕见 token 是关键知识”还是“它只是正确答案的一种写法”。
</div>
</section>

<div class="paper-card-copy" markdown="1">
<p class="visual-note-index">05 / Bounded contribution</p>

### BLL 限制的是梯度牵引，不是样本资格或损失值的硬截断

当前可核验材料支持的机制性质是：低概率区域内，单个 token 的 log-likelihood 梯度贡献有上界；在常规概率区域，行为仍接近最大似然。可用下面的不等式表达该性质：

$$
\left\lVert\frac{\partial\mathcal L_{\rm BLL}}{\partial z_t}\right\rVert\le C.
$$

$z_t$ 是 token 对应的 logit，$C$ 是上界。它说明这个 token 最多能把参数朝参考写法拉动多大力度；样本仍在，罕见写法也仍可以学。这里的式子是**性质级表达**，并非作者完整损失原式：同版本全文未在当前资料中可读，因此不能补写分段函数、阈值或梯度推导。
</div>
</section>

### 它发生在训练时：保留前向计算，调节反向贡献

可以把 BLL 的位置读成三步：先像普通 SFT 一样，对所有参考 token 计算条件概率；再对落入低概率区域的 token 限制其梯度牵引；最后将处理后的贡献与其余 token 一起反传到同一组参数。变化不在数据收集时，也不在模型生成答案以后。

这个位置解释了它的适用边界：它不能替代数据验证、去重或样本质量控制，也不是推理时的输出修复器。它处理的是“已经决定保留的监督，内部怎样分配优化力度”。
</div>
</section>

### 数据筛选、轨迹降权与 BLL 解决的不是同一层问题

| 操作 | 调节单位 | 它回答的问题 |
| --- | --- | --- |
| 数据过滤 | 一条样本 | 这条监督要不要进入训练？ |
| 轨迹降权 | 整段回答 | 这条监督整体占多大权重？ |
| **BLL-Loss** | 单个低概率 token | 留下后，哪一个 token 不应过度牵引更新？ |

三者可以组合，但不应该互相冒充。即使样本经过严格验证，仍可能含有可替换的低概率表面形式；反过来，即使某个 token 的贡献被限制，样本整体仍可能是事实错误或不安全的。这是把 BLL 放进实际后训练管线时最需要保持的层次感。
</div>
</section>

### 论文报告的是总体泛化改善，不是“低概率 token 都没用”

ICML / OpenReview 官方摘要报告：BLL-Loss 不引入额外可学习参数，并在多个模型、多个 reasoning benchmark 上改善泛化。这个总体结论和研究动机一致——模型可以学习专家演示的逻辑关系，而不必由某种罕见写法支配整次更新。

但这里必须保留证据边界：当前可直接读取的材料是摘要级，未提供可核验的同版本实验表、阈值、完整损失形态或逐项消融。因此本页不虚构精确增幅，也不把“稳定改善”外推为对所有任务与模型必然有效。
</div>
</section>

### 上界不是越紧越好：陌生也可能是真正的新知识

若上界太松，方法会接近标准 SFT；若上界太紧，真正尚未学会的知识也可能因低概率而被压低。代码中的一个标点、结构化输出的字段名、工具调用的参数或数学中的关键符号，都可能表面稀有却决定执行与答案正确性。

因此 BLL 不是“给低概率 token 打低价值标签”。它提出的是一个优化权衡：当参考答案存在多种正确实现时，如何防止可替换细节极端地垄断更新，同时不牺牲不可替代的任务信号。具体边界必须通过任务级实验验证。
</div>
</section>

### 低概率不等于低价值；关键是不让它自动拥有无限话语权

BLL-Loss 对 SFT 的追问并不大而化之：专家答案正确，为什么还要怀疑每个 token？答案是任务评价与逐字模仿的粒度不同。只要答案允许等价实现，低概率就既可能是能力缺口，也可能是风格差异。

该方法选择的折中是对低概率 token 的单点牵引设置边界，而不是把难样本或罕见写法从训练中删除。它把“多种正确实现”的问题留在模型可学习的空间里，同时要求我们更认真地验证哪里才是不可替代的任务信号。
</div>
</section>

## 附录与延伸讨论

以下为基于论文动机整理的待验证问题和工程检查项，不是论文已经给出的完整实现或结论。

### 若要评估这类损失，应额外拆开哪些变量？

1. **按 token 功能分组。** 将可替换的命名/措辞、知识实体、格式字符、结构化字段、代码控制字符等分开统计，避免只用整体低概率分布解释效果。
2. **并列任务正确性与表面匹配。** 对代码可记录测试通过与参考字符串相似度；对推理可分开评估最终答案、过程一致性和表达多样性，检验“宽容”是否真正保住正确实现。
3. **做上界敏感性分析。** 观察不同边界下的梯度分布、训练稳定性与下游表现，特别查验低概率但关键的 token 是否被系统性压制。
4. **使用等算力对照。** 与 label smoothing、focal loss、token reweighting 和数据过滤比较时，保持模型、数据、训练 token 数与调参预算可比，避免把预算差异误读为损失函数收益。

### 与 LALP 的关系

LALP 处理“多个正确长轨迹中该选哪一条”，通过局部步骤分数减少后文复读对数据选择的影响；BLL 处理“已选定轨迹中的每个 token 应该施加多大更新”，通过有界梯度限制极低概率 token 的过度牵引。两者的共同问题是监督信号的粒度，但一个位于训练前、一个位于训练中，不能互相替代。
