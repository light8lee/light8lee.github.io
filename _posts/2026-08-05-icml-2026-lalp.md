# 99.99% 的复读，为什么可能筛出更差的推理数据？

多位教师都给出正确的长推理时，最自然的一条未必最适合拿来训练学生模型。问题不在答案真假，而在评分时把整条轨迹压成一个 token 平均分：前面真正困难的推导只出现一次，后面反复引用其结论却会变得极高概率，最终反而由“容易复读”的部分主导排序。

ICML 2026 Spotlight 论文 [The Signal is in the Steps: Local Scoring for Reasoning Data Selection](https://openreview.net/forum?id=GcB3a6IonG) 提出 LALP（Local Average Log Probability）。它不替代答案正确性验证；在候选已经通过验证的前提下，它用学生模型在局部上下文中完成每一步的自然度，来挑选更适合蒸馏的推理轨迹。

> **本文主线：** 对长推理做数据选择时，应该区分“模型看过自己的结论后会不会顺着复读”和“模型能不能首次完成关键推理转移”。LALP 的两项操作正是局部化上下文、再按步骤而非 token 数量聚合。

### 一个很高的概率，可能只是在复制刚写出的答案

论文的 `1228` 例子把问题量化得很直观：模型第一次算出 $(2457-1)/2=1228$ 时，正确数字的概率约为 **71%**；后文引用 `1228` 时升至 **99.99%**，再用于后续算式时仍约 **99.4%**。三次出现的表面字符串相同，认知负担却不同：第一次要求计算，之后只需读取并复制已在上下文中的结果。

这就是 **self-conditioning artifact**：模型已生成的上下文让后续 token 容易，并不代表首个推理转移容易。LALP 不是惩罚重复，而是阻止长答案把“之后会复读”误算成“起初更值得教”。
</div>
</section>

### LALP 要挑的不是“读起来最顺”的答案

研究场景是多教师蒸馏：同一道题有多条**已经通过正确性过滤**的长推理，学生该学哪一条？LALP 的 *learnability* 不等于正确性，也不等于教师写得漂亮；它指该学生是否更可能从局部前提出发，吸收并在新题中复用这条推理转移。

论文同时研究两种粒度：先为每位教师整体排序，再在同一 prompt 的混合教师候选池中逐题选出一条轨迹。后者尤其接近真实蒸馏管线：它不用承诺“哪位教师永远最好”，而是利用不同教师在不同步骤上的互补性。
</div>
</section>

### 全局平均把不同性质的 token 混进一个票箱

全局平均 log probability（GALP）对整条回答的所有 token 做同权平均：

$$
\operatorname{GALP}(y)=\frac{1}{|y|}\sum_{t=1}^{|y|}\log p_\theta(y_t\mid x,y_{<t}).
$$

后文不会回头改写早期难步骤的分数；影响发生在候选**排序**上。重复、套话或结论复述会不断向总平均加入高概率 token，早期真正决定解题成败的低概率转移因而被稀释。论文进一步观察到，global 与 local 的分数差会随回答位置扩大，正是上下文累积带来的 self-conditioning 信号。
</div>
</section>

### 正确性与“对学生好不好教”是两道不同的门

LALP 不承担 verifier 的职责。答案是否正确、事实是否成立、代码是否通过测试，应先由外部验证器、答案比对或其他质量门槛处理；LALP 只在通过该门槛的候选间排序监督质量。

这一区分避免一个常见误用：把学生模型当前的自然度当作真值。低 LALP 可以意味着这条正确轨迹不适合当前学生，也可能意味着需要更大窗口或更好的步骤切分；它本身不能证明教师答案错误。
</div>
</section>

### 第一项改动：每一步只看题目与最近前提

将回答切为 $p$ 个步骤 $s_1,\ldots,s_p$。第 $i$ 步只看到问题 $x$、最近 $k$ 个前置步骤和该步骤内部 token：

$$
\operatorname{LocalLP}(s_i)=\frac{1}{|s_i|}\sum_{t=1}^{|s_i|}\log p_\theta\!\left(s_{i,t}\mid x,s_{i-k:i-1},s_{i,<t}\right).
$$

小窗口保留近处推导的必要条件，又减少遥远上文已经泄露答案的影响。论文的窗口消融以可用前缀步骤的比例衡量：**5%–25%** 的小窗口得到稳定、且与下游表现一致的教师排序；窗口增至 **50%–75%** 时，排序逐渐向 GALP 靠拢。这说明“局部”是方法有效性的核心条件，而非格式装饰。
</div>
</section>

<div class="paper-card-copy" markdown="1">
<p class="visual-note-index">06 / Step-level aggregation</p>

### 第二项改动：让步骤等权，而不是让长度决定话语权

LALP 再对步骤分数平均：

$$
\operatorname{LALP}(y)=\frac{1}{p}\sum_{i=1}^{p}\operatorname{LocalLP}(s_i).
$$

步骤内部仍是 token 平均；变化出现在步骤之间。一段 100-token 的展开和一段 10-token 的关键代入，各自都只得到一个步骤的权重。论文的 token 归因分析也显示，这种改动会把注意力从可预测的 discourse/filler 移开：GALP 的归因质量中 filler 占 **42.3%**，LALP 为 **18.7%**；数学符号从 **31.2%** 提升到 **48.6%**，推理连接词从 **12.8%** 提升到 **22.4%**。
</div>
</section>

### 为什么同一对候选会被两种聚合方式排出不同顺序？

卡片中的 A/B 是说明性例子，不是论文实验数据。A 在第一个短步骤上很难，却在后面 90 个 token 中反复复读；B 的两个步骤都较稳定。按 token 聚合，A 的大量容易 token 把平均值推高；按步骤聚合，A 的难步骤不能被长度淹没，B 因每一步都更可预测而被选中。

这个例子同时拆开 LALP 的两个作用：局部窗口降低“见过后再说”的虚高概率，步骤等权降低“写得更长所以更有票数”的影响。只使用其中一个改动，仍可能留下另一种粒度错位。
</div>
</section>

### 新题不一定像旧题，但局部动作可以重组

论文的泛化解释是覆盖密度差异：完整测试轨迹在训练集中通常近邻稀疏，而代入、定义设置、定理应用等局部步骤更容易找到相似支持。因此新题求解更像重组小动作，而不是检索一整条旧答案。

这不是把步骤当作完全独立的 token 块。LALP 仍让当前步骤读取最近 $k$ 步，承认局部前提链；它反对的是让极长的远程上下文无限制参与评分。这个假设也解释了为什么训练 loss 更低不必然带来更高泛化：最容易被整体拟合的轨迹，可能恰好包含最多“可复制但不可迁移”的部分。
</div>
</section>

### 具体改进：GALP 不只输给 LALP，甚至低于随机选择

在混合教师池中，论文为每个 prompt 从正确轨迹里选一条，形成 **817** 个样本的 curated dataset。对 Qwen2.5-32B-Instruct，七项数学评测的平均结果如下：

| 选择规则 | 平均分 |
| --- | ---: |
| Random | 0.651 |
| GALP（全局最高） | 0.632 |
| Local Lowest | 0.623 |
| **LALP（局部最高）** | **0.726** |

LALP 比 GALP 高 **9.4 个百分点**，也超过随机的 0.651；论文还报告它高于最强单一教师 QwQ-32B 的 0.719。这使结论更具体：在这个长轨迹、混合教师设置里，GALP 不只是噪声更大，而是可能系统性地排错了候选。
</div>
</section>

### 改进并非只出现在数学，但也不是放之四海皆准

用 LIMO 选择的数学数据训练后，论文还在 GPQA-Diamond 与 LiveCodeBench v2 评测迁移：GPQA-Diamond 从 GALP 的 **0.611** 到 LALP 的 **0.702**（+9.1 点）；LiveCodeBench-Hard 从 **0.232** 到 **0.261**（+2.9 点）。这些数字支持局部选择的收益并不限于数学平均分。

另一方面，论文复现了单一教师、短回答中 GALP 有效的既有现象。LALP 的优势针对的是长推理与多教师混合下的粒度错位；若任务需要真正的远距离依赖，窗口过短反而会遗漏关键信息。步骤切分质量、窗口大小和任务结构必须一起验证。
</div>
</section>

### 筛数据，别只问“整篇顺不顺”

LALP 的核心不是宣布“低概率步骤都更好”，也不是以局部评分替代正确性检查。它提出一个更窄、可检验的问题：若学生最终需要把局部推理动作重组到新题上，候选数据的排序是否也该主要审视这些动作的局部可支持性？

对长轨迹蒸馏而言，这个问题会暴露那些看似无害的 easy token：结论复读、模板化过渡和长篇解释能让全局平均很漂亮，却不一定提升首次推导的能力。
</div>

## 附录与延伸讨论

以下内容是根据论文边界整理出的工程讨论，不是论文已经验证的通用训练配方。

### 将 LALP 放入数据管线时，可额外记录什么？

1. **把正确性与可学习性分开保存。** 先保留 verifier、事实检查或答案比对的结果，再记录 LALP 作为正确候选之间的选择依据，避免评分器被误用为正确性判定器。
2. **同时审计 GALP 与 LALP。** 若二者分歧很大，可检查候选是否存在长重复、模板性结尾，或单个关键步骤被长解释掩盖；分歧本身不是自动删样本的理由。
3. **对窗口和切分做敏感性分析。** 在数学证明、代码轨迹、工具调用等任务上分别测试 $k$ 与步骤切分规则，观察排名是否稳定，尤其检查远程依赖是否被误伤。
4. **让选择成本进入评估。** LALP 需要步骤切分和多次局部打分；在比较训练收益时，应并列报告筛选成本、候选数、训练预算与下游泛化，而不只保留最终准确率。

### 与 BLL-Loss 的位置差异

LALP 和下一集的 BLL-Loss 都在追问“token 概率该怎样影响学习”，但操作位置不同：LALP 在训练前的候选轨迹层做选择，减少复读对整条数据分数的掩盖；BLL-Loss 在训练时的 token 层限制极低概率目标对更新的过度牵引。一个调整进入训练的轨迹，另一个调整已进入训练的局部优化力度。
